# C13: Relocatable kernelet memory (kernelet-physical addresses)

**Status:** adopted as the enabler of hibernation (the 5 s tier), of the kernel-level clone (C05's deferred variant) and of C08, and as a bound on page-table growth under C03; major revision after review. **Depends on kernelets:** yes, in mechanism: it gives a kernelet what the EPT gives a VM, a second naming of memory that the host may rebind, without a second-level page walk or a VM exit. **Acts on:** nothing by itself; it is what makes moving a kernelet's memory *possible*.

## The problem the reviews found

The Blueprint's Memory page (register D58) names every frame a kernelet holds by its **machine physical address**: the window maps `KW_PHYS + paddr`, vOSTD's `Frame` carries that `paddr`, and the kernelet writes it into the leaf entries of its own user page tables, which the CPU walks natively. That is the simplest possible design, and it is why `paddr_to_vaddr` and the frame code are the tree's own. It also means a kernelet's memory is **not relocatable**: the tenant's page tables, the kernelet's `Frame` objects, its allocator's free lists and its device descriptors all hold machine addresses, so a grain cannot come back under a different frame. The reviews of C03 and C05 found what that breaks: the first draft of C03 (host-transparent eviction) would let a tenant process read another tenant's frame through user-mode accesses that never fault, and a copy-on-write clone would map the template's frames.

Two consequences of D58 remain after those candidates were redesigned. A kernelet cannot be **moved as a whole**: not hibernated to disk and restored into other frames, not cloned, not migrated (C08), because its page-table roots, the level-3 and level-2 nodes its kernel half shares, and the host's registered root set and per-task CR3 records all hold machine addresses. And its window page tables **grow with the machine range it has ever touched**: D58 costs one `KW_PHYS` level-2 frame per GiB and one `KW_META` level-1 frame per 128 MiB of machine address space the kernelet has been granted, which under C03's churn of grains through the whole machine is a worst case of 4 + 32 MiB of page-table frames per kernelet on a 1 TiB server. What D58 does *not* break is C03 as redesigned: guest-side swap-out by swap slot, entries cleared by the kernelet, frames freed and grains returned, refaulted later into whatever fresh grains `grains_request` supplies; nothing in that path needs a grain back under its old name. The first draft of this page said C13 makes C03 sound; that was overstated, and the review corrected it.

## The mechanism

Give each kernelet its own **kernelet-physical address space**, dense, starting at 0, sized by `max_grains`; call its addresses `kpaddr`. This is what a guest-physical space is to a VM, and what Xen's paravirtualized guests had with their physical-to-machine (p2m) and machine-to-physical (m2p) tables.

- **The window is indexed by `kpaddr`.** `KW_PHYS + kpaddr` maps whatever machine frame the host currently backs that kernelet-physical page with, and `KW_META + kpaddr / 64` holds its metadata. Both stay host-written and sparse; a grant is a run of kernelet-physical grains bound to machine grains. The window page tables are now bounded by `max_grains`, not by the machine.
- **The p2m table**, one `u64` per kernelet-physical grain, host-written, read-only to the kernelet, in `KW_SHARED`, gives the machine address of each grain. Its bound is the kernelet's: an index at or beyond `max_grains` is a vOSTD panic, never a wrap.
- **The translation point is the PTE codec.** On the tree every present entry the page-table walker decodes is used as a `Paddr` at once: `PteStateRef::from_pte` borrows the child node by its address (`Frame::from_raw`, then `frame_to_meta`), the locking descent in `cursor/locking.rs` loads an entry and computes `paddr_to_vaddr` of it at every level, the lock and unlock walks decode every child, `PageTablePageMeta::on_drop` decodes every entry, `Entry::protect` decodes and re-encodes, and the huge-page split does arithmetic on the decoded address. So the only placement that is both correct and minimal is the architecture codec, `PageTableEntry::from_repr` (kpaddr to machine, through the p2m) and `to_repr` (machine to kpaddr) in vOSTD's `arch/x86/mm`; virtualizing "leaf writes and `query`" alone, as the first draft said, would translate twice in `protect` and miss the node pointers `alloc_if_none` writes. Everything above the codec, `Frame`, `Segment`, `paddr_to_vaddr`, the allocator, the metadata and the cursor, works in `kpaddr` and stays the tree's code: `Paddr` in vOSTD *is* `kpaddr`. Kernel-half entries are the exception: a kernelet copies `BootArgs::kernel_half_entries`, which are machine addresses of host-owned nodes with no `kpaddr`, into its roots, and vOSTD must never decode them (the cursor's range excludes the kernel half; the root's `on_drop` must skip it, a rule to state).
- **The reverse map is per kernelet, and lives in the entry.** The first draft put m2p in the owner array. That cannot work: the owner array is host memory, never mapped into a kernelet (mapping it would expose every tenant's machine layout, and a per-kernelet copy indexed by machine grain is 4 MiB per kernelet); and under C01 one arena grain is borrowed by many kernelets at different `kpaddr`s, so machine grain to (kernelet, `kpaddr`) is one-to-many and no host-wide array can answer it. The design instead carries the kernelet-physical grain index in the entry's ignored bits: bits 9–11 and 54–62 on x86-64 (bits 52–53 stay `AVAIL1`/`AVAIL2`) give 12 bits, 4,096 grains, **8 GiB of kernelet-physical space per kernelet**, and m2p becomes a shift with no table. A kernelet configured above 8 GiB needs the alternative, a host-written per-kernelet hash from machine grain to `kpaddr` in `KW_SHARED`, at 10–40 ns per decode; agent sandboxes do not need it.
- **Other consumers of addresses.** `pt_activate`, `tlb_shootdown`, `pt_root_register` and `pt_root_unregister` receive `kpaddr` roots and the host translates them (three host-side p2m lookups per call, cheap). `VmSpace::activate` compares the CR3 it reads (machine) with its `last_activated_paddr` and rebuilds a `Frame` from it; the Blueprint already virtualizes this per task, and the virtualized body must translate. Device descriptors carry `kpaddr`; `guest_memory(kpaddr, len)` translates through the kernelet's p2m under the same pin as today. `DeviceEntry.mmio_base`'s rule "above the host's highest physical address" becomes "above `max_grains × 2 MiB` plus the image region". C01's `image_map` returns a `kpaddr` base, its borrow table becomes the set of p2m ranges bound to arena grains, and `max_paddr()` reports the kernelet-physical top rather than the machine's.
- **Ordering of a bind.** The host writes the p2m entries, maps the window, then release-stores the run's state; the kernelet acquire-loads the run state before its first leaf write into the run. An unbind is the reverse, after the kernelet's entries are cleared (below).
- **Rebinding.** Moving a grain must also fix the entries that hold the *old* machine address. Two mechanisms, and the design takes **both**, for different cases. **(a) A host walk:** the host walks the kernelet's registered roots and its kernel root and rewrites every entry that points into a moved grain, decoding through the old p2m to `kpaddr` and re-encoding through the new one. This is the only mechanism that can move a kernelet **as a whole**, because the roots, the nodes shared with the kernel half, the registered root set and the per-task CR3 records hold machine addresses the kernelet cannot clear (they are its live page tables). A 60 MiB working set is on the order of a hundred page-table pages, 51,200 entries, **50–100 µs** to rewrite. **(b) Cooperative clearing:** for partial eviction (C03) the kernelet clears its own entries first, through the reverse mappings the kernel proper keeps for every mapped frame, when asked (`JOB_SHRINK` of C02 carries the target), and re-establishes them on the next fault through the tree's own minor-fault path, at which point the codec translates the leaf write through the p2m onto the new frame. (b) keeps the host out of tenant page tables and costs a fault per re-touched page after a restore, the same fault storm a VM pays through the EPT.
- **Host safety under (b) rests on vOSTD.** If vOSTD released a grain still named by a leaf entry, or left a stale TLB entry, the kernelet's user-mode code could read the frame after the host zeroed and re-granted it. The argument that this cannot happen from the kernel proper: page tables are written only by vOSTD, and a mapped `Frame` is owned by its entry and cannot be on a free list, so no kernel-proper bug can free a mapped grain. Two host-side measures make the rest independent of the kernelet: the host's release path (C02) must flush **all non-global translations on every CPU where any of the kernelet's roots has been active**, not only the window translation C02's first draft flushed; and in a hardened mode the host runs (a)'s walk over the released grain as a verification before reuse, at the 50–100 µs cost above.
- **The kernel-level clone still needs one more thing.** C05's "copy-on-write bindings" mean a write to a 2 MiB window page the host mapped read-only, which is a kernel-mode fault, and D22 kills a kernelet for kernel-mode faults. A host copy-on-write fault path for the window (copy the grain, rebind the p2m entry, rewrite through (a), resume) is needed and neither this page nor C05 specifies it; the kernel-level clone stays deferred.

## What it costs

- **Per page fault:** three to four m2p decodes on the descent plus one p2m lookup at the leaf write; a shift each with the entry-bits scheme, 10–40 ns each with the hash; **1–5 % of a 2–3 µs fault** either way, *estimated*. The first draft's "one lookup per entry written, none per access" counted only the writes.
- The p2m table: 8 bytes per grain, 4 KiB per GiB of kernelet-physical space.
- A whole-kernelet move: (a)'s walk, 50–100 µs per hundred page-table pages, plus the copy or the write-out itself.
- The `arch::mm` PTE codec of vOSTD becomes a virtualized item on the taxonomy page (internal to OSTD, no kernel-proper change); the identical-code list loses the codec and keeps the rest of `page_table`.
- **Relation to D58 and D13.** This is D13's naming with D58's mapping: `RunDesc` gains a `kpaddr` base and the grant table becomes the p2m, while `paddr_to_vaddr` stays D58's shift-and-add and the kernelet still writes no window page-table entry. The cost D58 cited against D13 (a radix lookup per `paddr_to_vaddr`) does not return; a new one (a lookup per PTE codec) appears; and assumption A13, that the window must cover the machine's physical range, is relieved, since the window covers `max_grains` instead.

## What it enables

- **Hibernation at the 5 s tier** as a real mechanism: a kernelet's private grains written out with their `kpaddr`, restored into whatever frames are free, its page tables rewritten by (a). Without C13 the 5 s tier keeps `m_fixed + m_kproc` (about 7 MiB) resident per idle kernelet instead of `m_fixed` (about 2 MiB).
- **The kernel-level clone** (C05's deferred variant), once the host copy-on-write path above exists.
- **Migration between NUMA nodes or to far memory (C08)**, by (a).
- **C03's page tables stay bounded** under grain churn: 4 KiB per GiB of `max_grains` rather than per GiB of machine range touched. This is a size bound, not a soundness requirement; C03 is sound under D58 with C02's unmap-and-flush.

## Isolation

The **kernel proper** never handles a machine address, which was already true under D58 (it could not write a page-table entry). What changes is inside vOSTD: the PTE codec is the one site that produces or consumes machine addresses (besides the copied `kernel_half_entries`), and a bad `kpaddr` from a vOSTD bug is caught by the p2m bound rather than naming an arbitrary frame. Against a compromise of vOSTD nothing holds, as everywhere in the design. The host's independence from the kernelet under partial eviction is stated above: the root-wide flush at release, and (a)'s walk as an optional check.

## Evidence

- Analytic: the tree's page-table code (`ostd/src/mm/page_table/{node/pte_state.rs, cursor/locking.rs, node/entry.rs}`, `arch/x86/mm/mod.rs`, `frame/mod.rs`, `vm_space.rs`) decodes entries at every level of every walk, which fixes the translation point; the review's counter-examples (a tenant PTE naming a reused frame; a clone mapping the template's frames) are the cases a rebind through the p2m removes.
- Published: Xen paravirtualization ran production guests on p2m/m2p tables for two decades. The Blueprint's User-mode page cites an earlier prototype's cold page fault at 10,345 cycles against 9,791 native (`src/blueprint/design/virtualizing-ostd/user-mode.md`); that prototype did not have a p2m, so the figure bounds the fault cost this design adds *to*, not the design itself.

## Changes to the Blueprint

Recorded here, not applied: `Paddr` inside vOSTD becomes the kernelet-physical address; the p2m table in `KW_SHARED`, bounds-checked; the `kpaddr` grain index in the ignored bits of every entry (bits 9–11, 54–62), with an 8 GiB kernelet-physical space per kernelet or a per-kernelet m2p hash above it; the PTE codec (`from_repr`/`to_repr`) virtualized, with a rule that kernel-half entries are never decoded; `pt_activate`, `tlb_shootdown`, `pt_root_register`, `guest_memory` and `image_map` take or return `kpaddr`; the `mmio_base` rule restated over `max_grains`; the host walk (a) as a control-half operation for hibernation, clone and migration; dirty tracking of kernel and user pages so that hibernation writes only what changed since the last cycle (a whole-state write per cycle is drive-bound at a fraction of the density, `../../bounds.md` §2.4); the release path's root-wide flush; register D58 revised to "window indexed by kernelet-physical address, mapped by the host; D13's naming with D58's mapping"; assumption A13 relieved; the Memory page's `RunDesc` gains the run's `kpaddr` base.
