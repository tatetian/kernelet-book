# API Virtualization: A Third Way Between Machine and OS Virtualization

**Abstract.** Machine virtualization draws the tenant boundary in hardware and pays thousands of cycles per crossing and a kernel per tenant. OS virtualization draws it in namespaces and cgroups, and every tenant shares the kernel's ambient authority. We propose a third boundary, *API virtualization*, for framekernels: Rust-based kernels whose unsafe code is confined to a small OS framework and whose remaining code is safe Rust written against the framework's API. We give each tenant its own instance of the unmodified kernel, a *kernelet*, running in the same address space as the host kernel and compiled against the same-yet-*virtualized* API of the OS framework. API virtualization lets arbitrary kernel code in a kernelet run seamlessly, as if it owned an entire machine, without interfering with or compromising other kernelets or the host.
