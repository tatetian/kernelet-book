# Introduction

Infrastructure that hosts mutually distrusting tenants has two ways to isolate them. *Machine virtualization* draws the boundary in the processor: a deprivileged mode, a second level of address translation, and a trap on every sensitive operation. The isolation is strong and the price is structural. An exit and re-entry cost thousands of cycles [1], a second scheduler runs beneath the guest's, and every tenant carries a kernel; microVMs [2] shave the fixed costs, not the per-crossing ones. *OS virtualization* draws the boundary in the kernel's own bookkeeping: namespaces partition names, cgroups meter resources, and a system call stays a function call. Its price is the mirror image. The kernel's authority is *ambient*, any code in it can name any global, and a tenant that finds a global the namespaces do not partition, or a resource the cgroups do not meter, has found its neighbors [3, 4].

This paper argues that a third place to draw the boundary exists on a kernel that already exists. A *framekernel* [5, 6] confines all unsafe code to a small framework (OSTD in Asterinas) and writes the rest of the kernel in safe Rust against the framework's API; everything such a kernel can do, it does by calling a name the framework exports. We virtualize that API. Each tenant runs an instance of the kernel proper, a *kernelet*, compiled unmodified against a *kernelet variant* of the framework we call *vOSTD*, virtual OSTD: the same OSTD source, built a second time under a `kernelet` configuration in which operations whose effect is local to the caller keep their implementation, operations that touch machine-wide state get a per-instance implementation over a small API the host's framework exposes, the *kernelet API*, behind which one component of the host kernel, the *endovisor*, supplies devices and policy, and operations a tenant must never have are not defined. Which of the three an item is can be read from the framework's own source, so the virtualized API cannot drift from the API it virtualizes; and the variant may use `unsafe` where the framework does, so it is not limited to what safe Rust can express. A kernelet cannot name a resource it was not granted; that part of the boundary is decided by name resolution and the build's dependency graph, since the kernelet crate depends on vOSTD under the name `ostd` and on nothing beneath it, and vOSTD reaches the host only through a table of C-ABI function pointers it receives when it is entered. What a kernelet holds, it holds as a name the host checks on use, never a pointer into the host. We call the combination *API virtualization*. Rather than partition the kernel's globals after the fact, it removes the tenant's ability to name them.

An instance is worth having only if it is cheap and if a misbehaving one can be contained and reclaimed. A kernelet is a *kernel-mode process*: a window of the address space, mapped only by its page tables, holds its private copy of the kernel's writable data and every frame it has been granted, at the same offsets the host's own linear map uses, so the kernel's per-tenant globals become per-instance and its memory code stays the framework's without a line of source changing. Its threads are threads of the host kernel, scheduled by the host. Devices are *virtio over function calls*, so there is neither a trap nor a VMM: a register access is a function call into the host, and a descriptor is checked against what the kernelet owns. Channels are vsock over the same path, switched and copied in the host; moving ownership of whole frames between kernelets is the stated extension. Containment rests on one discipline: the host enters a kernelet only to start a thread, and a kernelet enters the host only through the table, so one host-private bit per thread says whether the thread holds anything of the host's. A kernelet that must die is terminated where that bit is clear, its stacks discarded unread, and reclamation unmaps its window and releases its frames, running none of the kernelet's destructors.
