# Design register

Every decision the Design chapter makes where the Blueprint's fixed decisions left a choice, with the alternative rejected and the reason, and every assumption the chapter rests on. Entries are added as the pages are written and are numbered in the order taken. A reader who disagrees with a decision can find the page it takes effect on; a reader who wants to know what the design assumes can read the second list without the chapter.

## Decisions

| id | decision | rejected alternative and reason | page |
|---|---|---|---|
| D1 | The kernelet build of OSTD is the `ostd` crate under a Cargo feature `kernelet`, built with `--no-default-features`; the kernel crates gain a matching feature that drops the machine-facing components and turns on `forbid(unsafe_code)`. | A second package over the same source. It would let one Cargo build hold both variants, which nothing needs once the two images are separate builds, and it doubles the manifests. | [Builds and images](../blueprint/design/builds-and-images.md#two-builds) |
| D2 | Control and data cross the ELF boundary only through a service table and an entry table of `extern "C"` function pointers, exchanged at the image's entry point, plus shared pages; the host finds the entry point through `e_entry` and the entry table at a fixed offset. | Resolving host symbols by relocation at image-combine time, as a Linux module does. Direct calls instead of indirect ones, but it needs a merged symbol namespace or a relocation processor in the trusted base, and spreads the import surface over the symbol table instead of one versioned struct. | [Builds and images](../blueprint/design/builds-and-images.md#entry) |
| D3 | The kernelet image is linked at fixed addresses inside one top-level page-table entry, the kernelet window at entry 500, with every kind at the same addresses; compiled with `-C relocation-model=pic -C code-model=small` and linked as a static non-PIE executable so that the output has no relocations. | A position-independent image relocated at load. Allows several kinds in one page table and free placement, but needs a relocation processor in the trusted base, and no page table ever holds two kinds. | [Builds and images](../blueprint/design/builds-and-images.md#window) |
| D4 | Kernelet images are embedded in the host image with `include_bytes!` and their segments are copied into fresh frames at registration. | Bootloader modules (`MemoryRegionType::Module`), which allow replacing a kind without relinking; kept as the extension. Mapping the embedded bytes in place, which needs page alignment of the byte string and page-aligned segment offsets. | [Builds and images](../blueprint/design/builds-and-images.md) |
| D5 | The endovisor's hooks are a trait object per kernelet, called synchronously on the kernelet's own task inside the service call. | A request queue served by an endovisor thread: keeps host Linux code off the kernelet's stack, but turns every device register access into a cross-task round trip with a wakeup (9.4 µs where a function call is 35 cycles, measured on the booted prototype). | [Control half](../blueprint/design/kernelet-api-control.md) |
| D6 | Device models live in the endovisor, in the safe-Rust kernel proper; OSTD knows a device only as a register window and an interrupt line. | Device models inside OSTD's host build: smaller crossing, but puts Linux functionality (files, sockets) into the `unsafe`-bearing framework. | [Control half](../blueprint/design/kernelet-api-control.md) |
| D7 | The service half identifies the caller from a per-CPU slot the host scheduler writes, not from an argument on every call. | A context argument on every call: lets one function serve several kernelets on one stack, which nothing needs, and puts an unforgeable-by-convention pointer on every crossing. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D8 | Per-task records shared read-write carry only the kernelet's preemption count and a read-only mirror of the host's flags; the service-call depth, the flags themselves, the recorded page-table root and the saved user state are host-private per-task state. | Keeping the depth and flags on the shared page, as a first draft did: a kernelet could then hold its depth at one and never be killed. Service calls for the preemption count: on every lock, too many crossings. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D9 | Deferred work (virtual interrupts, ticks, grants, cancellation) is fetched by worker tasks through a parking service call; the host never enters the entry table except at task start. | Host-driven upcalls into the kernelet for each job: re-entrancy, and the service-call depth stops being a single bit. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D10 | The host bootstraps `KW_HEAP` at creation: it installs the window's level-2 tables in reserved frames at the head of the kernelet's runs, writes the level-3 entries, and maps the initial runs; OSTD (kernelet build) maps later runs by writing entries into those reserved frames. The kernelet never writes a page-table entry in host memory. | The kernelet mapping everything itself: it would have to write the host's level-3 table, and has no memory to bootstrap with before the first run is mapped. | [Control half](../blueprint/design/kernelet-api-control.md) |
| D11 | One worker task per virtual CPU, pinned to it, so the kernel proper's per-CPU tick and bottom-half code runs on the virtual CPU it believes it is on. | One worker per kernelet: fewer stacks, but per-CPU kernel code would run on the wrong virtual CPU. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D13 | A run's frame metadata lives at the head of the run, 8 frames per grain, after any reserved level-2 frames, reached through the heap window; the `mapping` module and `max_paddr` are the virtualized unit. | A separate `KW_META` region with one chunk per grain: keeps every frame allocatable, but needs its own tables, a bootstrap for the first chunk and a second mapping per grain. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D14 | *Withdrawn.* Page-table nodes are addressed through the window like every other frame; with the host bootstrapping the first run (D10), nothing needs a linear-map exception. | The earlier form of this decision, a linear-map exception for nodes, rested on a bootstrap the host now does. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D15 | The kernel proper's injected scheduler is inert inside a kernelet; the host schedules the kernelet's tasks within its group, honoring per-task priority and virtual-CPU hints. | Consulting the kernelet's scheduler as a second-level policy from the host's run queue: enters kernelet code from the scheduler's path with locks held, on a task that may not be the kernelet's, breaking the entry rule. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D16 | Kernel-mode preemption exists in the host build only for returns into kernelet text at service-call depth zero, honoring the task record's preemption count. | Kernel-mode preemption for host code too: a change to OSTD's whole lock discipline for no gain the design needs. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D17 | On an involuntary switch away from kernelet code the host saves the task's user FS and GS bases and FPU state, and restores them on the way back. | Forbidding kernel-mode preemption while user state is live in the CPU: every system call becomes a preemption-off region. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D18 | `InterruptLevel` is virtualized to report the level of the job a worker is delivering. | Leaving it identical, always task context: the kernel proper's interrupt-context checks would choose sleeping paths inside a delivered handler while the worker holds preemption off. | [Interrupts and time](../blueprint/design/virtualizing-ostd/interrupts-and-time.md) |
| D19 | Ticks are posted at `TIMER_FREQ` to busy virtual CPUs and at a policy rate `idle_tick_hz` (default 100 Hz) to an idle kernelet's virtual CPU 0; a one-shot `timer_arm` is the extension toward tickless idle. | 1 kHz per virtual CPU per kernelet regardless: a thousand wakeups per second per CPU for an idle sandbox. No idle ticks at all: a sleeping process's timer would never fire in an idle kernelet. | [Interrupts and time](../blueprint/design/virtualizing-ostd/interrupts-and-time.md) |
| D20 | The ring transition is one service call (`user_run`); the `execute` loop, the pre-run hook and the kernel-event check stay in the kernelet. | Moving the loop into the host: the kernel's `UserModeHooks` would cross the boundary as closures. | [User mode](../blueprint/design/virtualizing-ostd/user-mode.md) |
| D21 | A kernel-mode page fault in a user copy is resolved by the host jumping to the image's exception-table recovery address with the fault recorded in the task record; the kernelet's copy routine calls its own injected fault handler and retries. | The host calling the kernelet's injected handler from its fault path: enters kernelet code from the host's fault path. | [User mode](../blueprint/design/virtualizing-ostd/user-mode.md) |
| D22 | A page fault in kernelet code with no exception-table entry kills the kernelet (`KernelFault`), not the machine. | Treating it as a host panic, as the host kernel does for its own faults: a kernelet bug would reset the machine. | [User mode](../blueprint/design/virtualizing-ostd/user-mode.md) |
| D23 | Virtual devices are enumerated from the kernel command line the endovisor composes, reusing the kernel proper's MMIO bus probe with one `cfg` line for the interrupt step. | A kernelet-specific bus that reads `BootArgs` directly: a second probe to maintain. | [Devices](../blueprint/design/virtualizing-ostd/devices.md) |
| D24 | A descriptor outside the grant fails the request with the device's error status; it never kills the kernelet. | Killing on a bad descriptor: turns a tenant driver bug into a denial of service the tenant can trigger at will. | [Devices](../blueprint/design/virtualizing-ostd/devices.md) |
| D25 | The first version's network device is user-space backed through the kernelet runtime. | An in-kernel backend over a host tap or bridge: the host kernel has neither (A7). | [Devices](../blueprint/design/virtualizing-ostd/devices.md) |
| D26 | `main` runs on the boot task and parks when it returns. | Ending the kernelet when `main` returns: it returns before the init process runs. | [The rest](../blueprint/design/virtualizing-ostd/the-rest.md) |
| D27 | Init exiting ends the kernelet as `Exited(status)` through one `cfg` line, not as a panic. | Keeping the host's panic: the runtime could not tell a clean shutdown from a crash. | [The rest](../blueprint/design/virtualizing-ostd/the-rest.md) |
| D28 | Every caught panic is reported to the host through the `oops` service call. | Counting oopses only in the kernel proper: the budget could not be a host policy. | [The rest](../blueprint/design/virtualizing-ostd/the-rest.md) |
| D29 | The grant table and the physical-grain-to-slot radix are host-written pages in `KW_SHARED` that the kernelet only reads. | Kernelet-built tables from a descriptor list: no memory to build them in before the first run is mapped. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D30 | Memory is granted in physically contiguous, 2 MiB-aligned runs of grains; `grains_request` can ask for a contiguous run. | Single grains: caps a kernelet's largest contiguous allocation under 2 MiB, which the kernel proper's own file systems exceed. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D31 | `TaskOptions` gains `cpu_affinity` and `priority` builders and matching setters in both builds; the kernel proper forwards affinity, idle policy and priority through `cfg` lines. | No channel from the kernel proper to the host scheduler: per-CPU daemons would land on arbitrary virtual CPUs. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D33 | `GsBase::load` and `save` are virtualized to direct `IA32_KERNEL_GS_BASE` MSR accesses, since the tree's `swapgs` bracket is safe only with interrupts really disabled. | Leaving them identical under a preemption guard: a host interrupt between the two `swapgs` would run on the tenant's GS base, a host compromise. | [Virtualizing OSTD](../blueprint/design/virtualizing-ostd/index.md) |
| D32 | RCU grace periods are tracked per virtual CPU with an extended quiescent state for idle virtual CPUs. | Per-task quiescence: a period would wait for tasks parked for the life of the sandbox. Per-virtual-CPU without the extended state: a period never completes while any virtual CPU is idle. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D12 | Hooks do not sleep; host I/O behind a virtual device is done by an endovisor device thread per device, woken by the notify hook, charged to the kernelet by adoption into its scheduling group. | Sleeping hooks: a driver holds a spin lock across a register write, so a sleeping hook would sleep with preemption disabled. Doing I/O inline: same problem. | [Control half](../blueprint/design/kernelet-api-control.md) |

## Assumptions

| id | assumption | where it matters | standing |
|---|---|---|---|
| A1 | A kernelet's memory only grows: grains are granted, never reclaimed from a running kernelet; memory returns when the kernelet exits. A balloon is the extension. | [Control half](../blueprint/design/kernelet-api-control.md) | design choice, recorded |
| A2 | The refill cost of the window's non-Global translations after a CR3 write is acceptable without PCIDs. | [Builds and images](../blueprint/design/builds-and-images.md#window) | **[unverified]**; the Evaluation chapter measures it |
| A3 | A 64 KiB stack reserve is enough for the deepest host path a service call takes. | [Service half](../blueprint/design/kernelet-api-service.md) | *estimated*; to be measured on the host paths the device models use |
| A4 | The kernelet image's private writable state is under 128 KiB before per-CPU replicas. | [Builds and images](../blueprint/design/builds-and-images.md) | *estimated* from the tree's debug image (`.data` 27,464, `.bss` 23,944, `.cpu_local` 1,977 bytes) |
| A5 | The host kernel's file and socket objects can be driven by a kernel thread without a process context. | [Control half](../blueprint/design/kernelet-api-control.md) | **[unverified]**; the fallback is a borrowed process context on the device thread |
| A6 | A kernel-stack overflow in kernelet code is caught by a double-fault handler on its own interrupt-stack-table stack, at service-call depth zero, in a state from which the kernelet can be killed and the CPU switched away. | [Service half](../blueprint/design/kernelet-api-service.md) | **[unverified]** |
| A7 | A host-side software network interface registered with the host's network stack could serve as an in-kernel network backend, saving the user-space backend's two wakeups per frame. | [Devices](../blueprint/design/virtualizing-ostd/devices.md) | **[unverified]**; the host has no tap device or bridge today |
| A8 | The host can switch tasks from the interrupt-return path (`preempt_switch`) with every invariant of OSTD's trap and switch code intact. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) | **[unverified]** |
| A10 | The kernel proper's tick callbacks touch only shared, synchronized state of the interrupted thread, so the worker can deliver a tick with `Task::current()` overridden to that thread without a `cfg` line. | [Interrupts and time](../blueprint/design/virtualizing-ostd/interrupts-and-time.md) | **[unverified]**; the fallback is two `cfg` lines |
| A9 | Per-virtual-CPU RCU quiescence with an extended quiescent state is sound under every path by which a task can leave a virtual CPU. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) | **[unverified]** |
