# Design register

Every decision the Design chapter makes where the Blueprint's fixed decisions left a choice, with the alternative rejected and the reason, and every assumption the chapter rests on. Entries are added as the pages are written and are numbered in the order taken. A reader who disagrees with a decision can find the page it takes effect on; a reader who wants to know what the design assumes can read the second list without the chapter.

## Decisions

| id | decision | rejected alternative and reason | page |
|---|---|---|---|
| D1 | The vOSTD is the `ostd` crate under a Cargo feature `kernelet`, built with `--no-default-features`; the kernel crates gain a matching feature that drops the machine-facing components and turns on `forbid(unsafe_code)`. | A second package over the same source. It would let one Cargo build hold both variants, which nothing needs once the two images are separate builds, and it doubles the manifests. | [Builds and images](../blueprint/design/builds-and-images.md#two-builds) |
| D2 | Control and data cross the ELF boundary only through a service table and an entry table of `extern "C"` function pointers, exchanged at the image's entry point, plus shared pages; the host finds the entry point through `e_entry` and the entry table at a fixed offset. | Resolving host symbols by relocation at image-combine time, as a Linux module does. Direct calls instead of indirect ones, but it needs a merged symbol namespace or a relocation processor in the trusted base, and spreads the import surface over the symbol table instead of one struct checked by a source hash. | [Builds and images](../blueprint/design/builds-and-images.md#entry) |
| D3 | The kernelet image is linked at fixed addresses inside two top-level entries of the kernel half, entry 500 as the physical window and entry 501 for text, data, shared pages and the metadata window; every kind at the same addresses; built with `-C relocation-model=pic -C code-model=small -C link-arg=-no-pie`. | A position-independent image relocated at load: a relocation processor in the trusted base for nothing. Linking in the top 2 GiB with the tree's own flags: kernelet text under the host image's entry, a third level-3 table to copy per kernelet. | [Builds and images](../blueprint/design/builds-and-images.md) |
| D4 | Kernelet images are embedded in the host image with `include_bytes!` and their segments are copied into fresh frames at registration. | Bootloader modules (`MemoryRegionType::Module`), which allow replacing a kind without relinking; kept as the extension. Mapping the embedded bytes in place, which needs page alignment of the byte string and page-aligned segment offsets. | [Builds and images](../blueprint/design/builds-and-images.md) |
| D5 | The endovisor's hooks are a trait object per kernelet, called synchronously on the kernelet's own task inside the service call. | A request queue served by an endovisor thread: keeps host Linux code off the kernelet's stack, but turns every device register access into a cross-task round trip with a wakeup (9.4 µs where a function call is 35 cycles, measured on the booted prototype). | [Control half](../blueprint/design/kernelet-api-control.md) |
| D6 | Device models live in the endovisor, in the safe-Rust kernel proper; OSTD knows a device only as a register window and an interrupt line. | Device models inside OSTD: smaller crossing, but puts Linux functionality (files, sockets) into the `unsafe`-bearing framework. | [Control half](../blueprint/design/kernelet-api-control.md) |
| D7 | The service half identifies the caller from a per-CPU slot the host scheduler writes, not from an argument on every call. | A context argument on every call: lets one function serve several kernelets on one stack, which nothing needs, and puts an unforgeable-by-convention pointer on every crossing. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D8 | Per-task records shared read-write carry only the kernelet's preemption count and a read-only mirror of the host's flags; the service-call depth, the flags themselves, the recorded page-table root and the saved user state are host-private per-task state. | Keeping the depth and flags on the shared page: a kernelet could then hold its depth at one and never be killed. Service calls for the preemption count: on every lock, too many crossings. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D9 | Deferred work (virtual interrupts, idle ticks, grants) is fetched by worker tasks through a parking service call; the host never enters the entry table except at task start. | Host-driven upcalls into the kernelet for each job: re-entrancy, and the service-call depth stops being a single bit. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D10 | *Superseded by D58.* Formerly: the host bootstraps `KW_HEAP` at creation and the kernelet maps later runs by writing entries into reserved level-2 frames of its own grant. | | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D11 | One worker task per virtual CPU, pinned to it, so the kernel proper's per-CPU tick and bottom-half code runs on the virtual CPU it believes it is on. | One worker per kernelet: fewer stacks, but per-CPU kernel code would run on the wrong virtual CPU. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D12 | Hooks do not sleep; host I/O behind a virtual device is done by an endovisor device thread per device, woken by the notify hook, charged to the kernelet by adoption, through the CPU slot. | Sleeping hooks: a driver holds a spin lock across a register write, so a sleeping hook would sleep with preemption disabled. Doing I/O inline: same problem. | [Control half](../blueprint/design/kernelet-api-control.md) |
| D13 | *Superseded by D58.* Frame metadata lives in a sparse metadata window indexed by physical address, in host frames the host maps per grain, not at the head of the run. | | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D14 | *Withdrawn.* Page-table nodes are addressed through the window like every other frame; with the host bootstrapping the first run (D10), nothing needs a linear-map exception. | The earlier form of this decision, a linear-map exception for nodes, rested on a bootstrap the host now does. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D15 | The kernel proper's injected scheduler is inert inside a kernelet; the host schedules the kernelet's threads by their per-thread `nice` and virtual-CPU affinity, under the kernelet's quota. | Consulting the kernelet's scheduler as a second-level policy from the host's run queue: enters kernelet code from the scheduler's path with locks held, on a task that may not be the kernelet's, breaking the entry rule. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D16 | Kernel-mode preemption exists in the host build only for returns from the trap path into kernelet text at service-call depth zero, honoring the task record's preemption count; `preempt_switch` is the tree's own switch protocol (`before_switching_to`, `context_switch`, `after_switching_to`) entered with interrupts disabled and without the sleep assertion. | Preempting host code too: breaks the host's lock discipline. A switch path of its own that skips the tree's protocol: the resumed side would not run `after_switching_to`. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D17 | On an involuntary switch away from kernelet code the host saves the task's user FS and GS bases and FPU state, and restores them on the way back. | Forbidding kernel-mode preemption while user state is live in the CPU: every system call becomes a preemption-off region. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D18 | `InterruptLevel` is virtualized to report the level of the job a worker is delivering. | Leaving it identical, always task context: the bottom-half dispatch is `unreachable!` at level zero, the CPU-time statistics and process clocks charge nothing, and the softirq guard would run pending softirqs at the wrong time. | [Interrupts and time](../blueprint/design/virtualizing-ostd/interrupts-and-time.md) |
| D19 | Ticks are counted at `TIMER_FREQ` on busy virtual CPUs and posted at a policy rate `idle_tick_hz` (default 100 Hz) to an idle kernelet's virtual CPU 0; a one-shot `timer_arm` is the extension toward tickless idle. | 1 kHz per virtual CPU per kernelet regardless: a thousand wakeups per second per CPU for an idle sandbox. No idle ticks at all: a sleeping process's timer would never fire in an idle kernelet. | [Interrupts and time](../blueprint/design/virtualizing-ostd/interrupts-and-time.md) |
| D20 | The ring transition is one service call (`user_run`); the `execute` loop, the pre-run hook and the kernel-event check stay in the kernelet. | Moving the loop into the host: the kernel's `UserModeHooks` would cross the boundary as closures. | [User mode](../blueprint/design/virtualizing-ostd/user-mode.md) |
| D21 | A kernel-mode page fault in a user copy is resolved by the host jumping to the image's exception-table recovery address with the fault recorded in the task record; the kernelet's copy routine calls its own injected fault handler and retries. | The host calling the kernelet's injected handler from its fault path: enters kernelet code from the host's fault path. | [User mode](../blueprint/design/virtualizing-ostd/user-mode.md) |
| D22 | A page fault in kernelet code with no exception-table entry kills the kernelet (`KernelFault`), not the machine. | Treating it as a host panic, as the host kernel does for its own faults: a kernelet bug would reset the machine. | [User mode](../blueprint/design/virtualizing-ostd/user-mode.md) |
| D23 | Virtual devices are enumerated from the kernel command line the endovisor composes, reusing the kernel proper's MMIO bus probe with `cfg` lines for the interrupt and PCI steps. | A kernelet-specific bus that reads `BootArgs` directly: a second probe to maintain. | [Devices](../blueprint/design/virtualizing-ostd/devices.md) |
| D24 | A descriptor outside the grant fails the request with the device's error status; it never kills the kernelet. | Killing on a bad descriptor: turns a tenant driver bug into a denial of service the tenant can trigger at will. | [Devices](../blueprint/design/virtualizing-ostd/devices.md) |
| D25 | The first version's network device is user-space backed through the kernelet runtime. | An in-kernel backend over a host tap or bridge: the host kernel has neither (A7). | [Devices](../blueprint/design/virtualizing-ostd/devices.md) |
| D26 | `main` runs on the boot task, which exits when `main` returns. | Ending the kernelet when `main` returns: it returns before the init process runs. Parking the boot task: a 512 KiB stack held for the sandbox's life for nothing. | [The rest](../blueprint/design/virtualizing-ostd/the-rest.md) |
| D27 | Init exiting ends the kernelet as `Exited(status)` through one `cfg` line, not as a panic. | Keeping the host's panic: the runtime could not tell a clean shutdown from a crash. | [The rest](../blueprint/design/virtualizing-ostd/the-rest.md) |
| D28 | Every caught panic is reported to the host through the `oops` service call, from OSTD's `catch_unwind`, with the message stashed at the handler's entry. | Counting oopses only in the kernel proper: the budget could not be a host policy. | [The rest](../blueprint/design/virtualizing-ostd/the-rest.md) |
| D29 | The grant table is a host-written page in `KW_SHARED` that the kernelet only reads; it lists each run's physical base and length. | Having the kernelet keep its own copy from a call it must answer: an upcall. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D30 | Memory is granted in physically contiguous, 2 MiB-aligned runs of grains; `grains_request` can ask for a contiguous run. | Single grains: caps a kernelet's largest contiguous allocation under 2 MiB, which the kernel proper's own file systems exceed. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D31 | `TaskOptions` gains `cpu_affinity` and `nice` builders and matching setters in vOSTD; the kernel proper forwards a thread's affinity and `nice` through one `cfg` line each. | Leaving the hints out: the kernel proper's per-CPU daemons would land on arbitrary virtual CPUs. Adding the builders to the host build too: the host's threads already carry the attributes. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D32 | RCU grace periods are tracked per virtual CPU with an extended quiescent state for idle virtual CPUs. | Per-task quiescence: a period would wait for tasks parked for the life of the sandbox. Per-virtual-CPU without the extended state: a period never completes while any virtual CPU is idle. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D33 | `GsBase::load` and `save` are virtualized to direct `IA32_KERNEL_GS_BASE` MSR accesses, since the tree's `swapgs` bracket is safe only with interrupts really disabled. | Leaving them identical under a preemption guard: a host interrupt between the two `swapgs` would run on the tenant's GS base, a host compromise. | [Virtualizing OSTD](../blueprint/design/virtualizing-ostd/index.md) |
| D34 | A dying kernelet's tasks are terminated at service-call depth zero regardless of their preemption count. | Honoring the count until a budget expires: delays reclamation for no one's benefit. | [Faults](../blueprint/design/faults-and-reclamation.md) |
| D35 | Termination discards a task's stack rather than unwinding it. | Unwinding: runs the tenant's destructors on the host's behalf and cannot be done beneath a trap frame. | [Faults](../blueprint/design/faults-and-reclamation.md) |
| D36 | `destroy` never waits for a pin or an adopted thread; it returns `Zombie` and is retried. | Waiting inside `destroy`: blocks the runtime's process for as long as a device thread's host I/O takes. | [Faults](../blueprint/design/faults-and-reclamation.md) |
| D37 | All communication between a kernelet and the host or another kernelet is vsock over the ordinary device path. | A dedicated cross-kernelet channel with its own service calls: a second mechanism to secure and to learn. | [Channels](../blueprint/design/channels.md) |
| D38 | The vsock switch copies payloads in the first version; a frame-move extension is stated with its preconditions and left out. | Frame moves now: changes the ownership model and A1 before the copy path is measured. | [Channels](../blueprint/design/channels.md) |
| D39 | Host-side vsock endpoints are stream descriptors from the endovisor ABI, not a new `AF_VSOCK` family in the host kernel. | A host socket family: more surface than the runtime needs. | [Channels](../blueprint/design/channels.md) |
| D40 | The endovisor is a module of the kernel crate in safe Rust over the control half, not a module of OSTD. | Inside OSTD: it holds Linux functionality (files, threads) OSTD does not have. | [The endovisor](../blueprint/design/endovisor.md) |
| D41 | The endovisor ABI is one character device with typed `ioctl`s and pollable sandbox and endpoint descriptors, in the shape of `/dev/kvm`. | New system calls: nothing a runtime knows how to drive. | [The endovisor](../blueprint/design/endovisor.md) |
| D42 | Closing the last sandbox descriptor kills, waits for and destroys the kernelet. | Sandboxes outliving their runtime by default: a crashed runtime leaks them. | [The endovisor](../blueprint/design/endovisor.md) |
| D43 | A guest agent, as the kernelet's init, drives processes inside over vsock. | No agent: the runtime cannot start a process inside a kernel it cannot enter. | [The kernelet runtime](../blueprint/design/kernelet-runtime.md) |
| D44 | The root file system is an ext2 image built from the bundle, cached by content, attached read-only under an overlay inside; a `virtiofs` server backend in the endovisor is the planned replacement, the client existing on the tree. | The `virtiofs` backend first: the largest device model on the critical path of the first sandbox. | [The kernelet runtime](../blueprint/design/kernelet-runtime.md) |
| D45 | The first version's network is a user-space NAT in the runtime. | An in-kernel backend: the host has no tap or bridge (A7). | [The kernelet runtime](../blueprint/design/kernelet-runtime.md) |
| D46 | *Withdrawn.* Replaced by D66: a busy virtual CPU's ticks are consumed on the interrupted task, so the tick callbacks are identical code. | | [Interrupts and time](../blueprint/design/virtualizing-ostd/interrupts-and-time.md) |
| D47 | The user context passed to `user_run` must lie on the calling task's kernel stack; the host checks it. | A host-private per-task copy of the context, copied in and out on every round trip: two copies of about 160 bytes on the hottest path. | [User mode](../blueprint/design/virtualizing-ostd/user-mode.md) |
| D48 | vOSTD initializes the kernel proper's `PANIC_ON_OOPS` to `false`, enabling the oops path the host keeps off. | Leaving it off: every tenant-kernel panic ends the sandbox and the oops budget counts nothing. | [The rest](../blueprint/design/virtualizing-ostd/the-rest.md) |
| D49 | The `logger` component stays in the kernelet, and vOSTD sends every filtered record to `log_write` before the injected logger. | Making `logger` host-only: takes `print`/`println` out of the prelude and the kernel's log off the tenant's console. | [The rest](../blueprint/design/virtualizing-ostd/the-rest.md) |
| D50 | The notify hook validates chains and records them into an inbox preallocated at attach; the device thread pins and copies. | Copying in the hook: unbounded work under the driver's spin lock. Allocating in the hook: an allocation that can fail where nothing can sleep. | [Devices](../blueprint/design/virtualizing-ostd/devices.md) |
| D51 | The vsock switch rewrites `buf_alloc` in forwarded headers to the smaller of the advertised credit and the policy cap, and resets a sender that exceeds it. | Back-pressure by not draining the sender's transmit queue: stalls every connection on that device. | [Channels](../blueprint/design/channels.md) |
| D52 | `KERNELET_CREATE` only configures a sandbox; `KERNELET_START` calls `Kernelet::create` and `start` from the gathered configuration. | Creating the kernelet at `CREATE` and adding devices afterward: needs an `add_device` that mutates a created kernelet's boot arguments. | [The endovisor](../blueprint/design/endovisor.md) |
| D53 | Possession of a sandbox descriptor is the capability to operate on it; no per-call owner check. | A `Uid` check per `ioctl`: a credential lookup on every call, and a descriptor passed to another process becomes unusable. | [The endovisor](../blueprint/design/endovisor.md) |
| D54 | The sandbox boots and the agent handshake completes at OCI `create`; `start` only starts the container process. | Booting at `start`: `create` cannot fail on a bad environment, `kill` in `created` has nothing to signal, and the boot hides inside `start`. | [The kernelet runtime](../blueprint/design/kernelet-runtime.md) |
| D55 | Grains are zeroed at grant, before they are published. | Scrubbing at destroy: 2 MiB per grain on the destroy path, and the tenant's data stays in the frame while the kernelet is a zombie. | [Faults, termination, and reclamation](../blueprint/design/faults-and-reclamation.md) |
| D56 | `mark_dying` is a compare-and-swap, a store to the info page and a signal; the reaper task walks the task table, sends the reschedule interrupts, runs `on_dying`, clears jobs and deadlines, frees terminated tasks' stacks, and moves the kernelet to `Exited`. | Walking the task table in the detecting context: takes a lock inside the double-fault handler on a CPU that may hold it. Running `on_dying` there: a Linux-side hook inside an interrupt handler. | [Faults, termination, and reclamation](../blueprint/design/faults-and-reclamation.md) |
| D57 | The switch away from a kernelet task loads the host kernel root into CR3. | Flushing at destroy: a freed grant frame stays some CPU's live page-table root until then. | [Faults, termination, and reclamation](../blueprint/design/faults-and-reclamation.md) |
| D58 | The window is indexed by physical address: `paddr_to_vaddr(pa) = KW_PHYS + pa` and `frame_to_meta(pa) = KW_META + pa / 64`, both sparse, both mapped by the host through its linear map when it grants a grain, with the metadata in host frames charged to the kernelet. | A dense slot space with the metadata at the head of each run (D13) and the kernelet mapping later runs (D10): a radix lookup on every frame operation, a grant table with slots and reserved frames, and page-table entries written by the kernelet under tables the host installed. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D59 | Each kernelet task holds the `Arc<VmSpace>` it last activated, so a `VmSpace` is dropped only when no task holds it and `pt_root_unregister` never fails. | A pending list of page tables whose unregister was refused, retried at every activation: bookkeeping for a case the tree's own invariant prevents. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D60 | A TLB flush batch above four operations is one `tlb_shootdown` of everything non-Global under the root; a batch of one is one call. | One crossing and one interrupt round trip per operation: up to 32 of each per batch. | [Memory](../blueprint/design/virtualizing-ostd/memory.md) |
| D61 | A kernelet's tasks are threads of the host kernel proper, created through the `spawn_task` hook; `KerneletTaskBody::run` is OSTD's trampoline. | OSTD creating bare host `Task`s: the host's class scheduler enqueues only tasks that are `Thread`s. Teaching the scheduler a second kind of task: more kernel-proper code for less. | [Control half](../blueprint/design/kernelet-api-control.md) |
| D62 | The CPU quota is a throttle in OSTD driven by the host tick's per-kernelet charge; the weight is a per-thread `nice`. | A scheduler group with a weight and bandwidth control: the host has none, and building one is a scheduler project. | [Control half](../blueprint/design/kernelet-api-control.md) |
| D63 | Hook-bearing service calls run the hook on a per-CPU host stack with the host's preemption disabled, under `catch_unwind`; a panic in a hook kills the kernelet with `HostHookPanicked`. | Running hooks on the kernelet task's stack: the endovisor's depth becomes a tenant-reachable double fault when the reserve is wrong, and a panic in the endovisor halts the machine. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D64 | `KerneletConfig::max_tasks` bounds a kernelet's threads; their stacks are charged to its host-overhead account. | An unbounded task count: 512 KiB of host memory per thread at the tenant's discretion. | [Control half](../blueprint/design/kernelet-api-control.md) |
| D65 | No service call returns a value through a pointer; results come back in registers, virtual-CPU sets are a `u64` (`MAX_VCPUS = 64`), and the three read-only pointers are read with fallible copies. | Output pointers with a range check: a store through a pointer the kernelet chose faults when the kernelet unmaps the page. | [Service half](../blueprint/design/kernelet-api-service.md) |
| D66 | A busy virtual CPU's ticks are counted by the host into a shared per-virtual-CPU record and consumed by the kernelet's own task at its next tick point, in task context; only an idle kernelet's ticks are worker jobs. | Delivering every tick on the worker: two host context switches per millisecond per busy virtual CPU, and two `cfg` lines so that the callbacks can charge the interrupted thread. | [Interrupts and time](../blueprint/design/virtualizing-ostd/interrupts-and-time.md) |
| D67 | vOSTD spawns no idle threads: the boot CPU's idle loop becomes a thread that waits on init, the other idle loops are not spawned, two `cfg` lines. | Idle tasks parked and woken edge-triggered when a virtual CPU goes idle: a stack per virtual CPU and a wake protocol in the host's park and exit paths. | [Tasks](../blueprint/design/virtualizing-ostd/tasks.md) |
| D68 | Vsock reachability between sandboxes is deny by default; a runtime that holds both sandbox descriptors opens a pair with `KERNELET_VSOCK_POLICY`. | Allow within one user: on a node where containerd owns every sandbox, no policy at all. | [The endovisor](../blueprint/design/endovisor.md) |
| D69 | The kernelet build of OSTD is named **vOSTD**, virtual OSTD; the host build is plain **OSTD**, with "host build" said only where the build itself is the subject. | Symmetric names ("OSTD (host build)" and "OSTD (kernelet build)", or "host OSTD" and "kernelet OSTD"): they read as two peers, when one is the framework as it exists and the other a variant that presents its API. | [Boundaries and trust](../blueprint/design/principles.md) |
| D70 | The second version's devices are lending devices: rings in the kernelet's memory read through `guest_memory`, entries that lend the kernelet's own frames, host drivers that take those frames as DMA targets. | Keeping virtio and changing only the backend: the descriptor walk, the device thread and the copy stay. Rings mapped read-write on both sides: below the isolation floor. | [Zero-copy I/O](../blueprint/design/zero-copy-io.md) |
| D71 | The host acts only on bytes it copied out of a submit entry, validated in host memory; network and channel headers travel inside the entry. | Parsing headers or lengths in the tenant's frames: the tenant can change them after the host's check. | [Zero-copy I/O](../blueprint/design/zero-copy-io.md) |
| D72 | Lending is enforced twice: ownership in vOSTD (the `DmaStream` a `BioSegment` holds; the frame a network driver keeps until completion) and a 16-bit lend count in the host's owner-and-lend word (slot 16, generation 32, count 16), advanced by one compare-and-swap with the owner check and rolled back if a later segment fails; a lent grain is never released, moved or freed, and the count is in destroy's drain list. | Either alone: rests on the other side's correctness. A separate check and count: a move or destroy can interleave. A 32-bit count: does not fit the word. | [Zero-copy I/O](../blueprint/design/zero-copy-io.md) |
| D73 | Submission happens in the notify hook, at most 32 entries per call, non-sleeping, into a `submit_nowait` of the host driver; a device thread exists only for a backend that must sleep. Until the tree's block layer has `submit_nowait` (A14), block pays one host-thread wakeup per batch. | A thread per device on the fast path: the wakeup the model removes. An unbounded pass over a 256-entry ring: up to a millisecond under a spin lock. | [Zero-copy I/O](../blueprint/design/zero-copy-io.md) |
| D74 | Interrupt suppression is one polling bit the kernelet writes, with a `SeqCst` fence on both sides of the two-flag hand-off: set by the driver above four initiated requests in flight and polled from the kernel proper's own per-device threads; for receives set on interrupt and cleared when the ring is drained. | Virtio's event index: more state for the host to validate. No fence: a missed completion is a hang until the next one. Counting posted receive frames toward the threshold: a network device would poll forever. | [Zero-copy I/O](../blueprint/design/zero-copy-io.md) |
| D75 | Network receive is zero-copy only with a per-kernelet receive queue; a shared queue costs one host copy and is stated as such. | Claiming zero-copy receive on a shared queue: the device does not know the destination before the packet lands. | [Zero-copy I/O](../blueprint/design/zero-copy-io.md) |
| D76 | Inter-kernelet transfer copies once, frame to frame, in the sender's notify hook, into a frame the receiver posted for that connection; the receiver's advertised credit is exactly its posted frames, so a send without a posted frame is a protocol error, not a queued packet; the copy is capped at 16 KiB per entry. Moving whole grains stays the Channels extension. | Two copies through device threads (D38). A host queue between the rings: two copies again, and the head-of-line stall D51 rejects. Moving grains here: a grain is the unit, so nothing smaller can move, and the preconditions are the Channels page's. | [Zero-copy I/O](../blueprint/design/zero-copy-io.md) |
| D77 | On bare metal a kernelet's grains are mapped into the host's IOMMU domain at grant, not per request. | Per-request IOMMU map and unmap: an invalidation per request, microseconds. | [Zero-copy I/O](../blueprint/design/zero-copy-io.md) |

## Assumptions

| id | assumption | where it matters | standing |
|---|---|---|---|
| A1 | A kernelet's memory only grows: grains are granted, never reclaimed from a running kernelet; memory returns when the kernelet exits. A balloon is the extension. | [Control half](../blueprint/design/kernelet-api-control.md) | design choice, recorded |
| A2 | The refill cost of the window's non-Global translations after a CR3 write is acceptable without PCIDs. | [Builds and images](../blueprint/design/builds-and-images.md#window) | **[unverified]**; the Evaluation chapter measures it |
| A3 | A 64 KiB stack reserve is enough for the deepest host path a service call takes. | [Service half](../blueprint/design/kernelet-api-service.md) | *estimated*; to be measured on the host paths the device models use |
