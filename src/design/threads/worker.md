# The worker: deferred work by name, in thread context

Kernel work queues, softirq handlers, timers and interrupt callbacks all take `Send + 'static` closures today, and four of the queues are machine-wide statics. A shared queue is an unattributed cross-kernelet channel and a kernelet closure run by the host. So: **deferred work is an entry point, not a captured reference.** A work item is a `JobId` the kernelet minted; the host validates the kernelet is alive and runs `KerneletEntry::run_job(kernelet, job, cpu)` on the **kernelet's own worker task**, a host-owned task in the kernelet's group. The worker is Alternative B's interrupt-handler task under another name, and one property of that design is kept: the worker runs at the top of its group's priority, so an event (a virtio completion, a timer, a vsock delivery) is handled before any of the kernelet's ordinary threads run, which is what gave Alternative B its latency. The worker loops over jobs with a catch per job, so a panicking job costs an oops and not the kernelet's only worker; and it is the kernelet's own so that a job blocking on a kernelet mutex pins nobody else.

The facade's `IrqLine::on_active(closure)` stores the closure in the kernelet's own table under a fresh `JobId` and registers that name with the host; the host never sees the closure. Timer expiries that only wake a sleeping thread never enter the kernelet at all.
