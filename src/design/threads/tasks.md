# Tasks are host-owned; the kernelet names them

A `Task` is a host object charged to the kernelet fallibly, on the soft band of [§4.3.3](../memory/bands.md). It carries `(KerneletId, ThreadRef)`, the kernelet's kernel page table or a bound `VmSpace`, the thread's registers and XSAVE area (moved out of the kernel's `ThreadLocal`, which is what the tree's own comment names as the prerequisite for kernel preemption), a pending-signal bit, the four [attribution words](../memory/arena.md), a page-table reservation and the entry frame of [§4.7.1](../faults/tiers.md). Its two opaque data slots, which hold the kernel's `Arc<Thread>` and `ThreadLocal` today, hold nothing from a kernelet's arena: OSTD drops the outgoing task's slots on the *successor's* page table, where the outgoing kernelet's window may not be mapped. The 34 sites that reach the current thread through those slots become lookups in the kernelet's own thread table by `ThreadRef`. Kernelet code never holds `Arc<Task>`; the facade's `Task` is a `ThreadRef`, an index plus a generation, and its `Task::current()` reads the current task's `ThreadRef` from the host. Spawning is two halves: the kernelet records what the thread should run in its own table under a fresh `ThreadRef`, then asks the host for a task with the child's initial registers; the task's first act is `KerneletEntry::thread_main(kernelet, t)`. No closure crosses.

OSTD's `Waker` becomes name-based, and OSTD gains park-by-name and unpark-by-name over an OSTD-owned name table; that removes the wake path's write into another task's `Arc`, which today is a cross-kernelet handoff in a shared wait queue.
