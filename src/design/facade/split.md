# What moves to the host, entry points, and kernelet kinds

The split of the kernel tree is Alternative A's, kept: the scheduler policy, timer core, VT and console backends, work-queue container, softirq spawner, interface poller, the thread-state protocol, the panic handler, `main`, the OSTD hooks and the component registration move to `endovisor`, about 13,000 lines; the sixteen driver components (39,341 lines) become host code, including the PCI transport and the physical virtio drivers for real devices. What stays in `aster-kernelet` is the kernel proper, about 110,000 lines, *plus* the virtio MMIO transport and the virtio device drivers (block, net, console, vsock, about 6,000 lines of the 8,339 in the virtio component) as front-ends over the facade's `IoMem`, which is Alternative B's split and the opposite of Alternative A's.

Control enters a kernelet through four **entry points**, a trait `KerneletEntry` the kernelet crate implements and the host calls on a host-owned task: `thread_main` (a thread's body, today's user-task loop), `page_fault` (a kernel-mode fault taken in a user copy, re-entered beneath a trap frame under its own catch), `run_job` (deferred work by name, [§4.4.6](../threads/worker.md)), and `thread_exit`. The host's `reenter(kernelet_id, job)` is the one function that admits a job: it checks the kernelet's phase and generation in a single compare-and-swap, sets the [attribution words](../memory/arena.md), and calls `run_job` on the kernelet's worker.

**Kernelet kinds.** Because the boundary is a crate, the image may contain more than one kernelet crate: a Linux-ABI kernel, and, say, a minimal real-time kernel or a single-purpose network function, each with its own data-window template and its own front-end drivers, all against the same facade. Alternative B wanted this and proposed dynamic loading to get it; here it is a build-time list, each kind is a `(crate, template, entry points)` triple in the host's table, and the "no `unsafe`, same compiler" properties are properties of the one build that produced the image. Nothing later in this book depends on more than one kind existing.
