# Vsock, and what a tenant sees

Inside a kernelet, this is `AF_VSOCK`: the kernelet's virtio-vsock front-end driver (a `VirtioDev` of type vsock) exposes the standard socket family, each kernelet has a context id the host assigned, the host is CID 2, and the connection state machine, control opcodes and credit-based flow control follow the virtio-vsock specification, with one deliberate deviation Alternative B also made: control messages are function calls, not queue entries. A tenant's programs therefore use the same socket API they would use to talk to the host of a microVM, and a multi-agent framework that already speaks vsock needs no change.

What crosses is bytes. Application data is copied from the tenant's user memory into the `RRef<DataPacket>` on `send(2)` and out of it on `recv(2)`, two copies against a pipe's two and virtio-vsock's three-plus-exits. **Cross-kernelet file-descriptor passing does not exist**, because an `Arc<dyn FileLike>` is an object graph; `SCM_RIGHTS` works within a kernelet only. A zero-copy path for large payloads, gifting whole user frames from the sender's `VmSpace` to the receiver's, is possible under the same owner-array discipline and is listed in [§7.2](../../limitations/todos.md) with its precondition.
