# Passthrough

For a kernelet that needs a device to itself (a NIC queue pair with SR-IOV, an NVMe namespace, an accelerator), Alternative B's passthrough mode is adopted as the `Passthrough` handle kind: the host hands the kernelet a *real* `IoMem` over the device's registers, a `DmaStream` constructor restricted to the kernelet's own frames, and an interrupt line; it programs the IOMMU so that the device can address only frames owner-tagged to that kernelet, and routes the device's interrupt to a CPU in the kernelet's affinity set, where the host's handler posts the kernelet's registered job. The register access is then a real MMIO through OSTD's `IoMem`, not a function call, and the DMA is the device's. The IOMMU domain is torn down and the interrupt masked at destroy, before frames are released, and a frame under DMA is pinned until the device says it is done, which is the same wait the destroy sequence already makes for virtio.

What passthrough does not give a kernelet is authority over anything but that device: the `IoMem` covers the device's range and no other (OSTD's I/O allocator already refuses sensitive ranges), the IOMMU is host state, and interrupt remapping is host state.
