# The problem the windows solve

Every kernelet runs the same code. The kernel has, by a census of the linked image, 318 writable objects: 96 of them are per-tenant state in the kernel proper (the PID table, the UNIX-socket namespaces, the mount table, the page cache's wait-queue array, the RNG, the work queues, about ninety more), 208 belong to drivers and subsystems that become host code, 11 are immutable after boot, 3 are unresolved. If two kernelets run the same code against the same `static PID_TABLE`, they share a PID table, and the design is over before it starts.

Alternative A's answer was to rewrite the 96 into fields of a per-kernelet struct. Alternative B's answer, sketched and not built, is the one every operating system uses for user programs: **give each instance its own copy of the writable sections, at the same virtual address, through its own page tables.** A `static` is then per-instance without the source knowing. This design builds that answer, extends it to the heap, and pays for it in three places, taken in the order a reader needs them: a page-table switch policy ([§4.1.3](switch-policy.md)), a linker contract ([§4.1.4](data-window.md)), and a heap that addresses its slots through the window ([§4.1.5](heap-window.md)).
