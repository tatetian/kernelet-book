# What the process gives the rest of the design

Three consequences shape the later layers. First, the kernel's `static`s need no rewrite, so the facade ([§4.2](../facade/index.md)) can be OSTD-shaped and the kernelet crate can be the kernel with a short list of edits rather than a long one. Second, a kernelet task and a host task are distinguishable by their page table, so "is the current task a kernelet task" is a per-task fact the host records once and the switch path restores, which is what the attribution words of [§4.3.1](../memory/arena.md) are. Third, destroying a kernelet is unmapping two windows and releasing their frames ([§4.7.4](../faults/destroy.md)); anything that pointed into them is dead memory, and a host bug that kept such a pointer faults in thread context rather than reading the next tenant.
