# Runtime, from the only booted numbers there are

The booted prototype is not this design, but it is the same shape on the same base, and its numbers bound what this design should expect: a boundary crossing at function-call cost (35 cycles); a page fault at native cost (within 6% of Asterinas itself); an ownership transfer at 177 cycles; a cross-kernelet round trip at 9.4 µs where a native pipe is 4.3 and virtio-vsock is 36.9; and, on the other side of the ledger, 39 cycles per crossing for the stack check and 104 + 94 cycles to create and destroy each transferred buffer. What the prototype did not measure, and this design adds on top, is the resolver (about 16 cycles in a model), the host scope switch (two stores), the owner-array read per descriptor and per free, the magazine path, and the CR3 writes and window flushes of [§4.1.3](../design/process/switch-policy.md). A cycle count from *this* design's kernel does not exist, and the performance claim is a hypothesis until it does.
