# The same design as two answers

*Why is what remains shared safe?* Because every shared thing is one of three: read-only after boot (the image's text and rodata); reachable only through a facade item that the host implements with per-kernelet accounting (the service trait, the virtio backends, the RRef table, the allocators); or host-internal and never entered with a kernelet callback.

*What is proven, checked, argued?* Proven: `vostd`, for the memory-management API ([§3.5](tcb.md)). Decided by the build: the dependency closure ([§4.2.2](../design/facade/crate-graph.md)), the section placement ([§4.1.4](../design/process/data-window.md)), the sealed traits ([§4.2.4](../design/facade/services.md), [§4.6.2](../design/channels/rref.md)), the type bounds on what crosses ([§4.2.4](../design/facade/services.md), [§4.6.2](../design/channels/rref.md)). Worth proving: the resolver's seven checks ([§4.2.4](../design/facade/services.md)), the death-reserve bound ([§4.3.3](../design/memory/bands.md)), that the two windows are the only kernel-half mappings that differ between page tables ([§5.2](../implementation/checks.md), check 7). Argued: bounded host lock holds ([§4.4.3](../design/threads/scheduler.md)), the completeness of the drain list ([§4.7.4](../design/faults/destroy.md)), and the frame-reset obligation outside `vostd` ([§7.2](../limitations/todos.md), item 0).
